# 平台上架下架任务与数据中台 - 第一阶段工作包

## 文档目的

用于把第一阶段 `1688 中台 v1` 拆成可以直接开发的工作包，明确输入、输出、边界和验收方式。

## 适用范围

- 当前阶段：第一阶段
- 当前目标：`1688 中台 v1`
- 当前边界：只围绕现有 `1688/T-005` 执行层做包装与接入

## 工作包拆分

### WP-01：1688 适配器包装

- 目标：
  - 把现有 `T-005` 执行层封装为 `1688 adapter v1`
- 输入：
  - `ERP/furniture-uploader` 现有入口与运行报告
- 输出：
  - 适配器调用接口
  - 统一执行结果结构
  - 适配器能力声明
- 不包含：
  - 重写现有 Selenium / 页面执行主链路
- 验收：
  - 适配器可被独立调用
  - 结果能输出标准状态、错误、工件路径

### WP-02：任务中心与状态机

- 目标：
  - 实现 `task/task_item` 创建、状态流转、队列和调度
- 输入：
  - 第一阶段数据库结构
  - 状态机口径
- 输出：
  - 任务创建服务
  - 调度器
  - 状态流转逻辑
- 不包含：
  - 第二平台调度
- 验收：
  - 任务可从 `created` 走到 `success/failed/partial_success/cancelled`
  - 状态更新和统计字段一致

### WP-03：锁与执行资源治理

- 目标：
  - 支持 `shop/account/session` 级锁
- 输入：
  - 店铺和执行环境配置
- 输出：
  - 锁申请与释放逻辑
  - 锁超时或租约机制
- 不包含：
  - 多机复杂负载均衡
- 验收：
  - 同店铺同会话任务不会并发执行

### WP-04：数据快照与标准商品模型

- 目标：
  - 任务创建时冻结输入数据
  - 定义标准商品模型
- 输入：
  - `jst_sku / jst_skumap_view / op_ShopConfig_view`
  - 现有 1688 模板字段
- 输出：
  - `source_snapshot`
  - 标准商品模型结构
  - 快照生成器
- 不包含：
  - 在线规则平台
- 验收：
  - 重试时可不依赖实时源数据
  - 标准商品模型可支撑现有 1688 执行需要

### WP-05：三层映射与版本绑定

- 目标：
  - 实现 `源数据 -> 标准商品模型 -> 平台发布模型`
- 输入：
  - 映射配置
  - 快照数据
- 输出：
  - 映射转换器
  - 映射版本记录
- 不包含：
  - 图形化规则管理后台
- 验收：
  - 映射结果可复现
  - 执行记录中能追踪 `mapping_version`

### WP-06：结果落库与工件归档

- 目标：
  - 统一记录执行结果和工件
- 输入：
  - 适配器执行结果
  - 运行报告、截图、HTML 等工件
- 输出：
  - `task_attempt`
  - `task_artifact`
  - 查询接口
- 不包含：
  - 复杂 BI 报表
- 验收：
  - 任意任务都能追踪尝试记录和工件路径

### WP-07：受控回流与回流事件

- 目标：
  - 用 `reflow_event` 表管理结果回流
- 输入：
  - 已标准化的执行结果
- 输出：
  - 回流事件出箱逻辑
  - 回流处理器
  - 回流失败重试机制
- 不包含：
  - 直接同步修改外部视图
- 验收：
  - 回流事件可重试
  - 回流状态可查询

### WP-08：简版运营入口

- 目标：
  - 提供最小可用的运营操作页面或入口
- 输入：
  - 已完成的任务中心和查询接口
- 输出：
  - 任务创建页
  - 任务列表页
  - 任务详情页
- 不包含：
  - 完整权限系统和复杂报表
- 验收：
  - 运营可独立创建任务并查看结果

## 推荐开发顺序

1. `WP-01` 1688 适配器包装
2. `WP-02` 任务中心与状态机
3. `WP-03` 锁与执行资源治理
4. `WP-04` 数据快照与标准商品模型
5. `WP-05` 三层映射与版本绑定
6. `WP-06` 结果落库与工件归档
7. `WP-07` 受控回流与回流事件
8. `WP-08` 简版运营入口

## 第一阶段最低验收口径

- 可以创建 1688 上架任务
- 可以生成任务项和输入快照
- 可以调度并调用 `1688 adapter v1`
- 可以记录执行尝试、工件和结果
- 可以生成并处理回流事件
- 可以在简版运营入口看到任务状态和失败原因
