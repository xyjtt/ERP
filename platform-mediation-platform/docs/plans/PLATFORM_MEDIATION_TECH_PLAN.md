## 需求理解

当前项目不适合直接按“大而全”路线重建全平台系统。更可行的方式是保留现有 `1688/T-005` 执行层，把它包装为第一个平台适配器，在此基础上先建设任务中心、数据快照、三层映射、结果落库和受控回流，形成 `1688 中台 v1` 的最小闭环。

## 方案概述

- 方案摘要：先做 `1688 中台 v1`，再用第二个平台验证抽象，最后扩展为全平台中台
- 核心思路：控制面和执行面分离，现有 1688 执行器作为适配器接入
- 是否分阶段交付：是，分三阶段

## 设计原则

- 原则 1：保留现有 `T-005` 主执行链路，不重写执行器
- 原则 2：任务执行必须绑定 `mapping_version + source_snapshot + adapter_version`
- 原则 3：结果先落中台，后受控回流，不直接回写外部系统

## 影响范围

- 前端：新增简版运营入口，用于任务创建、查看状态和查看结果
- 后端：新增任务中心、调度器、适配器注册、快照与回流能力
- 数据库：新增适配器、快照、尝试、工件、回流事件等表
- 接口：新增任务创建、查询、执行、回流相关接口
- 运维/发布：先按 Windows 环境和轻量后台 worker 落地
- 测试：补任务中心闭环测试、适配器测试、回流测试和重试测试

## 实施方案

### 模块拆分

- 模块 1：任务中心
  负责任务创建、状态机、队列、调度、重试、锁管理。
- 模块 2：映射与快照
  负责源数据冻结、标准商品模型、平台发布模型和版本绑定。
- 模块 3：平台适配器
  负责封装现有 `1688/T-005`，执行发布动作并返回标准化结果。
- 模块 4：结果与回流
  负责结果落库、工件归档、回流事件生成与同步。
- 模块 5：简版运营入口
  负责任务创建、状态查看、失败原因查看和工件查看。

### 关键流程

- 流程 1：任务创建
  业务侧提交任务 -> 中台生成 `task/task_item` -> 生成 `source_snapshot` -> 绑定 `mapping_version`
- 流程 2：任务执行
  调度器取队列 -> 申请 `shop/account/session` 锁 -> 调用 `1688 adapter v1` -> 写入 `task_attempt` 和 `task_artifact`
- 流程 3：结果回流
  任务结果标准化落库 -> 生成 `reflow_event` -> 由回流同步器异步处理外部同步

### 数据与接口影响

- 新增数据：
  - `platform_adapter`
  - `source_snapshot`
  - `task_attempt`
  - `task_artifact`
  - `reflow_event`
- 变更数据：
  - `task`
  - `task_item`
  - `shop_config`
  - `platform_category_mapping`
- 新增接口：
  - 任务创建接口
  - 任务状态查询接口
  - 工件查询接口
  - 回流事件处理接口
- 变更接口：
  - 第一阶段尽量不修改现有 `T-005` 外部行为，只做包装和接入

## 方案备选与取舍

- 备选方案 A：重写 1688 执行器并直接建设全平台统一执行层
- 未采用原因：风险高、工期长、会破坏现有已跑通的执行基线
- 当前方案优势：复用现有成果、缩短落地周期、降低抽象失败风险

## 开发计划

- 阶段 1：封装 `T-005` 为 `1688 adapter v1`，建立最小任务中心闭环
- 阶段 2：接入第二个平台，验证适配器和映射抽象
- 阶段 3：扩展多平台与多执行方式，补完整运营台

## 测试与验证计划

- 单元测试：
  - 任务状态机
  - 适配器包装层
  - 快照与映射转换
  - 回流事件生成
- 集成测试：
  - 任务创建到执行完成闭环
  - 失败重试与幂等
  - 锁机制与串行保护
- 联调验证：
  - `1688 adapter v1` 与现有执行仓联调
  - 受控回流链路联调
- 上线前检查：
  - 数据一致性
  - 日志与工件可追踪性
  - 关键表索引与约束有效性

## 风险与依赖

- 风险 1：RPA 执行链路仍受平台页面变化影响
- 风险 2：第二个平台选择不当，会延迟适配器抽象验证
- 外部依赖 1：聚水潭数据源和权限
- 外部依赖 2：平台账号、登录态和 AI 素材接口

## 验收口径

- 功能验收：
  - 能从中台创建 1688 任务并调度执行
  - 能记录快照、尝试、工件和回流事件
- 稳定性验收：
  - 执行闭环稳定，失败可以定位并可重试
  - 锁机制可以避免同店铺会话并发冲突
- 发布验收：
  - 第一阶段只要求 `1688 中台 v1` 可用，不要求多平台同时上线
